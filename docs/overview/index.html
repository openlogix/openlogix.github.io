What is Open Logix?

  • An open source foundation for enabling FPGA design tools.
  • Free to use and adapt, under MIT or Apache 2.0, your choice.
  • An extensible, open board model and catalog.
  • An MCP engine to build, verify and program the boards.
  • An intuitive open API for third-party tools, AI agents and automation, in any language.
  • Ready-made frontends for IDE, command-line and schematic-based design.
  • Runs on macOS, Windows and Linux.

Logix Catalog

Every FPGA board, described once.

  • FPGAs and boards: definitions of the supported FPGAs and boards.
  • Board resources: LEDs, buttons, clocks, UARTs, headers and more, mapped to FPGA pins.
  • Custom boards: users provide their own definitions, in the same format.
  • Source of truth: drives FPGA operations and code generation.
  • Designed for partial information: boards start with what's known and grow over time.
  • Language independent: based on standard JSON.
  • Open data: one readable JSON file per board, usable by any tool in any language.
  • Grows with the community: a custom board becomes a contribution with one pull request.

Logix Engine

One engine. Every FPGA tool.

  • Abstracts FPGA operations: build, verify, simulate and program the board.
  • Manages its tools and catalog: no setup by the user.
  • Intuitive API: standard MCP over stdin/stdout.
  • Any language: a frontend launches it as a child process and calls its tools.
  • For AI agents and plain programs: IDEs, scripts and CI use the same API.
  • Self-discovery by AI agents: for ad-hoc operations, scripts and frontends.
  • Explicit and stateless: each request names its files, folders and board.
  • One native executable: nothing else to install.

Logix Frontends

Many ways to work. One engine.

  • Built on Logix Engine and Catalog: reuse data and logic, focus on the user experience.
  • Their own model: each defines its own project model and design paradigm.
  • Their own examples: each creates its examples based on Logix Catalog.
  • Simple installation: one download, no toolchain to install.
  • Third-party frontends welcome: leveraging the Logix API and sample frontends.

Logix IDE

The Arduino experience, for FPGAs.

  • An Arduino-like IDE frontend: inspired by Arduino's minimalist look and feel.
  • The whole design cycle: edit, verify, build, test, simulate and run on the board.
  • Simple installation: one download, no toolchain to set up.
  • Manages its dependencies: Logix Engine, Logix Catalog and their tools.
  • Simple projects: the sources and a small project file in a single directory.
  • Custom boards, if needed: use your own board definitions.
  • Ready to start: example projects, and template projects for new ones.
  • Runs on macOS, Windows and Linux. Available Q4 2026.

AI agents, directly

Any MCP agent can use Logix Engine, with no frontend.

  • Connect once: add the engine to an agent such as Claude Code.
  • Ask in plain words: the agent learns the tools from the engine itself.
  • End to end: it writes the design, builds it and programs the board.
  • Done already: an agent changed a design, built it and programmed an Alhambra II through the engine alone.
  • Runs on macOS, Windows and Linux. Available Q4 2026.
# connect the engine to Claude Code, once $ claude mcp add logix-engine -- logix-engine \ --engine-folder ~/.logix-dev/engine > Make the LED on my Alhambra II blink once a second, then program the board. ● get_catalog the board's clock and LED pins ● writes main.v and pinout.pcf ● build synthesis, place and route ● list_devices finds the connected board ● program_board ✓ Programmed. The LED blinks once a second.

AI agents write scripts

A one-off request becomes a repeatable operation.

  • Ask once: "Write a Python script that builds my project and programs the board."
  • Run it anytime: from the shell, a Makefile or CI, with no AI involved.
  • Any language: Python, JavaScript, Rust or any other language with an MCP client.
  • Runs on macOS, Windows and Linux. Available Q4 2026.
# program.py: build the project and program the board import asyncio, os from mcp import ClientSession, StdioServerParameters from mcp.client.stdio import stdio_client ENGINE = StdioServerParameters(command="logix-engine", args=["--engine-folder", os.path.expanduser("~/.logix-dev/engine")]) SRC = os.path.abspath("."); BUILD = SRC + "/_build" async def main(): async with stdio_client(ENGINE) as (r, w), ClientSession(r, w) as s: await s.initialize() await s.call_tool("build", {"board": "alhambra-ii", "top_module": "main", "source_folder": SRC, "source_files": ["main.v"], "constraint_file": "pinout.pcf", "build_folder": BUILD}) found = await s.call_tool("list_devices", {"build_folder": BUILD}) device = found.structuredContent["devices"][0]["id"] await s.call_tool("program_board", {"build_folder": BUILD, "device": device}) asyncio.run(main()) # error handling left out

Third-party frontends

Anyone can build on Logix Engine and Logix Catalog. A few ideas:

  • Editor extensions: JetBrains, Neovim, Emacs or Zed (Logix VSCode covers VS Code).
  • Python and other languages: Amaranth, LiteX or MyHDL designs, built and programmed by the engine.
  • Test automation: scripts and CI that build designs, run testbenches and program boards.
  • Tool testing: regression suites that check the open source FPGA tools on many boards.
  • Education: classroom tools, lab setups and automatic grading of student designs.
  • Board makers: factory tests and setup tools, using the board's catalog entry.

Looking ahead

Longer-term goals.

  • Remote development: work with boards anywhere on the network, with Logix Remote.
  • Shared libraries: reusable design code across frontends, with Logix Lib.
  • Closing the test loop: tests that run on the real board, with Logix HIL (hardware in the loop).
  • Learning: Logix training material and media.
